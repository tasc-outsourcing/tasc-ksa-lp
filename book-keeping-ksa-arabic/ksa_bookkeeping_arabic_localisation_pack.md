## Arabic localisation and RTL implementation pack

Source page: https://lp.tascoutsourcing.sa/book-keeping-ksa/

Recommended Arabic URL: `https://lp.tascoutsourcing.sa/ar/book-keeping-ksa/`

This pack is written for direct use by Codex. It preserves the offer, page order, visual identity, HubSpot lead flow and service coverage of the English page. The Arabic is adapted for Saudi business readers and is not a literal machine translation.

## 1. Non negotiable decisions

1. Do not redesign the landing page.
2. Create an Arabic copy of the existing English page in a separate route.
3. Set the document to `lang="ar"` and `dir="rtl"`.
4. Use the Arabic copy in this file exactly unless a legal or commercial owner approves a change.
5. Keep the TASC Corporate Services logo exactly as supplied. Never mirror the logo.
6. Preserve all HubSpot form actions, field names, hidden values, UTM capture and lead routing.
7. Translate visible form labels and option labels, but do not translate or change backend values sent to HubSpot.
8. Use Saudi Arabia as the default country and `+966` as the default dialling code. The English page currently defaults to the United States, which should not be copied.
9. Do not use automatic browser translation or a translation plugin at runtime.
10. Do not publish a mixed English and Arabic interface.
11. Keep emails, telephone numbers, prices, percentages and legal entity names in left to right isolation so they display correctly inside Arabic text.
12. Do not mirror photographs, the logo, the WhatsApp mark or other brand marks. Mirror only layout order and directional interface elements.

## 5. RTL layout specification

### Document foundation

Use this at document level:

```html
<html lang="ar" dir="rtl">
```

Use this at CSS foundation level:

```css
html[dir="rtl"] {
  direction: rtl;
}

html[dir="rtl"] body {
  text-align: right;
}

.ltr,
[dir="ltr"] {
  direction: ltr;
  unicode-bidi: isolate;
}
```

Do not fix RTL by adding `text-align: right` to every element. The layout must be structurally RTL.

### Component mirroring

1. Hero copy sits on the right. The consultation form sits on the left.
2. On mobile, keep the hero copy first and the form second.
3. Service category labels sit on the right and accordion content sits to their left.
4. In the Why TASC section, copy sits on the right and the image sits on the left.
5. Footer columns read from right to left.
6. Accordion chevrons and directional arrows must reverse direction.
7. Check marks, plus signs, WhatsApp marks, photographs and the TASC logo must not be flipped.
8. Keep number strings, percentages, email addresses and telephone numbers in explicit left to right wrappers.

Example:

```html
<span dir="ltr">SAR 4,999</span>
<span dir="ltr">675+</span>
<span dir="ltr">5%–25%</span>
<a dir="ltr" href="mailto:info@tascoutsourcing.com">info@tascoutsourcing.com</a>
```

| `margin-left` | `margin-inline-start` |
| `margin-right` | `margin-inline-end` |
| `padding-left` | `padding-inline-start` |
| `padding-right` | `padding-inline-end` |
| `left` | `inset-inline-start` |
| `right` | `inset-inline-end` |
| `border-left` | `border-inline-start` |
| `border-right` | `border-inline-end` |
| `text-align: left` | `text-align: start` |
| `text-align: right` | `text-align: start` for ordinary content |

Do not use negative letter spacing for Arabic. Do not assign fixed heights to text cards, accordion rows, headings or buttons.

## 6. Arabic typography

### Preferred font

Use `IBM Plex Sans Arabic` if no licensed Arabic brand font is available. It is clean, professional and has enough weights for this page.

If TASC owns a web licence for `DIN Next Arabic`, use that instead. Do not substitute an unlicensed font.

Recommended stack:

```css
font-family: "IBM Plex Sans Arabic", "Noto Sans Arabic", Arial, sans-serif;
```

### Font weights

| Use | Weight |
| --- | --- |
| Hero heading | 700 |
| Section headings | 700 |
| Card headings | 600 |
| Buttons and labels | 600 |
| Body copy | 400 |
| Supporting copy | 400 or 500 |

Avoid weight 800 or 900 for long Arabic headings. It becomes dense and damages readability.

### Type scale

| Element | Desktop | Tablet | Mobile | Line height |
| --- | --- | --- | --- | --- |
| Hero heading | 46 to 50 px | 40 px | 31 to 34 px | 1.25 to 1.32 |
| Section heading | 34 to 38 px | 30 to 32 px | 25 to 28 px | 1.3 to 1.38 |

### Text behaviour

1. Use `letter-spacing: 0` for Arabic.
2. Allow natural wrapping. Do not insert manual line breaks unless the design requires one stable break at desktop size.
3. Use Arabic punctuation.
4. Keep paragraph width controlled. Long Arabic lines should not exceed roughly 65 characters where practical.
5. Use `font-feature-settings: "kern" 1;` only if the selected font renders it cleanly.
